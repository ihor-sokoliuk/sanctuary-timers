# Validation record

Local verification on Windows x64, 2026-09-25, using Zig 0.15.2 targeting baseline `x86_64-windows-gnu`:

- 28 core cases passed: parsing/validation, event boundaries and local recurrence, malformed data, changed schedules, cache estimates, deferred/coalesced refreshes, retry behavior, clock jumps, request budget, settings, placement, startup policy and hit testing.
- Platform suite passed: preferences/cache file roundtrips, corrupted input fallback and executable/window helpers. This suite uses temporary files and does not register startup or use the network.
- Rendering suite passed: actual DirectWrite text metrics for all 12 supported font sizes, countdown/label fit, independent background alpha and opaque glyphs, forced device-resource recreation, hidden drawing and foreground preservation.
- Offscreen executable smoke check passed: successful layered render, correct no-activate/click-through styles, no visible window and no foreground change.
- Packaged executable is 973,312 bytes and uses the Windows GUI subsystem. It requires no separately installed language runtime.
- First normal launch registered the quoted executable path in the current user's Run key. With another application foreground, it initially made zero event reads and zero paints. Foreground identity was unchanged across launch.
- The real Diablo session triggered one successful HTTP 200 read for each of the three records. All anchors validated, persisted, and rendered with zero drawing errors. Repeated natural focus changes did not trigger extra reads. A second launch left one application process running.
- At the actual 21:55 UTC Helltide end, the adapter performed one successful Helltide read at exactly 21:55:20 UTC. Its count advanced from one to two; Boss and Legion remained at one each. This directly verified the event-specific 20-second delay in the running game session. The overlay remained visible with Diablo foreground, with zero drawing/request failures at the final observation.
- Passive Win32 inspection confirmed visible, topmost, no-activate windows while Diablo retained foreground; the drawing surface has the transparent input style and its controls stay within its bounds. Natural user interaction opened appearance settings, changed text/width/opacity and position, and returned to the timer view. Preferences were persisted without test automation changing them. The panel adapted between 100% and 150% display scaling. No test automation moved the mouse, sent keys, or selected a window.
- A 47.96-second mixed-focus observation consumed 0.078125 CPU seconds (0.163% of one logical core, 0.0068% of this 24-logical-processor machine), with 30.60 MiB working set and 14.56 MiB private memory at its end. A subsequent 69.95-second observation including natural appearance/drag interaction consumed 0.890625 CPU seconds (1.27% of one core, 0.053% of the machine), ending at 33.71 MiB working set and 17.20 MiB private memory. These short samples are not a long-duration load benchmark. Handles decreased from 332 to 313 across the latter interval.
- Independent MSVC build and all three CTest suites passed in [Windows CI](https://github.com/ihor-sokoliuk/sanctuary-timers/actions/runs/36193815770). The locally running executable was built with Zig; the CI artifact uses MSVC.

Core behavior and review regressions were exercised as failing tests before their fixes. The rendering integration suite was then used to verify native drawing and resource recovery. All three suites passed before normal application launch.

## Limits

Typography refinement, September 25: a regression check initially failed because the renderer returned Segoe UI. After embedding PT Serif, tests verified the actual private font collection, real regular/bold faces without synthetic weights, and actual label/countdown metrics at all 12 supported sizes. The complete core/platform/renderer suites passed before application replacement. The original executable size above describes the initial sans-serif build; embedding the two font faces adds approximately 683 KiB. Initial performance observations above predate this typography refinement.

The revised executable is 1,678,336 bytes. Its offscreen smoke check passed without focus change, and it replaced the running overlay while preserving the existing settings file byte-for-byte. [Independent MSVC CI](https://github.com/ihor-sokoliuk/sanctuary-timers/actions/runs/36194895074) passed the new font checks and all other suites. The preview image shows the updated serif rendering.

No mouse or keyboard input is synthesized during verification. Appearance state, placement, DPI changes and focus transitions were observed during natural user activity; the comfort of dragging, collapse, and actual gameplay click-through still require user confirmation. Monitor unplugging and Windows logon were not exercised. Pure startup policy tests cover preserving disablement/removal; actual Task Manager toggling has not been exercised. Request budget/cancellation logic is tested, but a hostile slow-chunk HTTP server is not part of the suite. A cancelled request may finish its current WinHTTP operation (up to the configured 4-second timeout) before exiting. No comparative performance claim against another overlay has been measured.
